# GitHub upstream code review for requested sources

Review target: use the GitHub repository references already cited in `flixfun-upstream-audit.md` to compare protocol details with Elfura Sources 4, 5, 7, 9, 11, 12, 13, 15 and 16. Upstream code is an extraction reference, not proof of current provider availability, correct title matching, or playable audio.

## Repository findings and Elfura decisions

- **ScreenScape / Nxsha — [Skywave22/Plugins-TJ Nuvio provider](https://github.com/Skywave22/Plugins-TJ/tree/643cb268eab2c62a9f6017ee8ae928e188d39715/src/screenscape) and [upstream SkyStream plugin](https://github.com/Skywave22/Plugins-TJ/blob/643cb268eab2c62a9f6017ee8ae928e188d39715/src/screenscape/plugin.skystream.js), inspected at commit `643cb268eab2c62a9f6017ee8ae928e188d39715` (2026-11-02).** The Nuvio wrapper calls the same encrypted `/api/servers` → `/api/sources` flow, resolves via TMDB ID, and supplies episode runtime in the plugin URL. Its `src/_lib/nxsha.js` contains an empirically selected 14-server order for NuvioTV (`mhbox`, `awsind`, `rive-citadel`, `nitro`, `em-8`, `xdownloader`, `castle`, `k4khdhub`, `streamflix`, `vidapi`, `hdhub4u-direct`, `rive-flowcast`, `vixolity`, `k4khdhub-direct`); on NuvioTV it keeps only these and orders them because providers run serially, while phone clients use the full list concurrently. Elfura now uses that order as the front of its shared catalog, with Nxsha taking the first 12 and ScreenScape the next six, so their parallel server-side requests stay bounded and distinct. The upstream plugin excludes `ophim`, caps each server at four rows, rejects HDHub-family outputs for TV, and checks HLS duration against expected episode runtime. Elfura follows the first three safeguards; duration checking remains a gap because expected runtime is not currently passed to SourceQuery. The upstream plugin uses mirror/relay code that is deliberately not copied. This is reference implementation evidence only, not live availability/playback evidence.
- **VixSrc — [sakinator/hostreamio](https://github.com/sakinator/hostreamio/blob/b022280ed079394b3046ab597ab5863450b30436/lib/upstream/services/scraper/sites/vixsrc.dart).** The reference uses the same `/api/movie/{tmdb}` and `/api/tv/{tmdb}/{season}/{episode}` routes as Source 9. It explicitly unescapes `\\u0026`, `\\/` and backslashes from embedded playlist values, and carries the player language (`lang`, default `en`) into the signed playlist request. Source 9 now decodes those escaped values and supplies the safe language parameter; it still only exposes the audio evidence found in the returned manifest. This is a protocol-parity correction, not evidence that current 403/404 probes are repaired.
- **Mapple — [sakinator/hostreamio](https://github.com/sakinator/hostreamio/blob/b022280ed079394b3046ab597ab5863450b30436/lib/upstream/services/scraper/sites/mapple.dart).** The historical extractor captures `window.__REQUEST_TOKEN__` without constraining its alphabet. Source 15's current page-token regex only accepted URL-safe characters, which could silently stop the flow before `playback-init`; the parser now accepts bounded opaque punctuation and the fixture covers `+`, `/` and `=`. The current Mapple workflow has not yet confirmed that live requests proceed beyond the page, so this is a targeted hypothesis to test, not a success claim. Current site routes and protocol are still from `mapple.fun`; do not blindly copy the old `mapple.club` host.
- **VidZen — [kacigaya/binje/lib/vidme.ts](https://github.com/kacigaya/binje/blob/main/lib/vidme.ts).** Binje confirms the page token is in escaped React Server Components data, requests use `/api/sources` with `type`, TMDB `id`, season/episode, server and token, and only HLS rows from the provider's `/api/stream/` path are accepted. Source 12 follows that shape and has the same general server list, intentionally excluding Proxima. No protocol change was justified from this repository alone; live candidate reachability remains title-dependent.
- **Xpass — [kacigaya/binje/lib/vidsu.ts](https://github.com/kacigaya/binje/blob/main/lib/vidsu.ts).** Binje uses the Xpass JSON endpoint with the player Referer and accepts HLS rows. Source 13 follows the same route but applies stricter signature, host, episode metadata, and SSRF checks before liveness testing. Keep those restrictions; don't weaken the host allowlist just to increase raw candidates.
- **Anivexa — [walterwhite-69/Anivexa-API](https://github.com/walterwhite-69/Anivexa-API/tree/421fb8d9c62aed5e6cca17a63526292e5240f21a).** Its worker exposes `/episodes/{provider...}/{anilistId}?map=false`, which runs a caller-selected provider subset and avoids Anime-ID mapping when Elfura only needs episode lists. Source 16 now uses the documented filtered endpoint with the same complete provider set and `map=false`, preserving provider coverage while avoiding irrelevant mapping work. The upstream filtered handler still waits on its selected provider functions, so the main cold-fanout cost may remain; tests verify request shape and late-result behavior, not a live latency improvement.
- **VidZee — [utubysdog/free-movies-api/providers/vidzeeCrypto.js](https://github.com/utubysdog/free-movies-api/blob/main/providers/vidzeeCrypto.js).** This is VidZee (not VidZen/Source 12): the repo documents a replacement plaintext `e=0` API and names its own server IDs, including `v6:Hindi`. Its relevant Elfura integration is Source 8, outside this focused requested list. Keep the distinction clear; never infer Hindi audio merely from a server label.

## Changes made from repository comparison

- Source 9 now mirrors Hostreamio's escaped player-value handling and `lang` query behavior. Regression fixtures cover escaped `\/`/`\\u0026` values and a single-language manifest as well as multi-audio.
- Source 15 now parses opaque bounded Mapple request tokens, with a fixture proving punctuation survives into the `playback-init` JSON body.
- Nxsha / ScreenScape lane selection now starts with the NuvioTV-measured 14-server order, with Source 5 querying the first 12 available lanes and ScreenScape the next six without overlap. Both sources default on unless explicitly disabled; `.env.example` documents the opt-out. The adapters skip `ophim`, and Nxsha limits fetched rows to four per lane. TV requests also drop HDHub-family IDs to avoid season-pack / mismatch candidates.
- The upstream TV-duration comparison is documented but not ported: Elfura does not currently pass episode runtime through `SourceQuery`, and a separate metadata fetch inside a source adapter would add latency and network load. Existing manifest audio evidence, HLS safety checks and positive liveness verification remain authoritative; provider labels and upstream behavior are not playback proof.
- No source was removed or promoted based on upstream claims. The external reference and all automated results are not live provider-availability checks.

Validation for this focused change: `npm run build:backend`, the Nxsha and ScreenScape adapter tests, full `npm test`, full `npm run typecheck`, and `git diff --check` passed. This proves the mocked regression cases and project checks only; live availability and verified playback were not established.
